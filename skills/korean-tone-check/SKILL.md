# 한국어 말투·AI 티 점검 (korean-tone-check)

존댓말로 쓰기로 한 글에 "했다", "좋아" 같은 반말이 한 줄만 섞여도 독자는 바로 알아챕니다. 이 스킬은 그런 종결어미를 기계적으로 먼저 찾아내고, 그다음에 사람이 판단해야 하는 상투어와 리듬 문제를 표시합니다.

## 언제 쓰나요
- 발행 직전의 블로그 글, SNS 글, 카드 문구, 영상 대본, 자막
- "존댓말로 통일해 줘", "AI 티 빼 줘", "번역투 고쳐 줘" 같은 요청

## 절차
1. **목표 말투를 정합니다.** 사용자가 정한 말투가 없으면 물어봅니다. 공개 SNS와 정보성 글은 보통 `hamnida`(~습니다), 친근한 채널은 `haeyo`(~해요), 칼럼·기사는 `plain`(~다)입니다.
2. **검사를 돌립니다.**
   ```bash
   node scripts/check-tone.mjs draft.md --target hamnida
   node scripts/check-tone.mjs draft.md --target haeyo --json   # 기계가 읽을 결과
   ```
   제목(#), 해시태그 줄, 인용문(""), 코드, 표는 검사하지 않습니다. 명사로 끝나는 표제형 문장도 판정하지 않습니다.
3. **`[말투]` 줄은 반드시 고칩니다.** 종료 코드가 1이면 목표와 다른 종결이 남아 있다는 뜻이므로, 고친 뒤 다시 돌려 `PASS`가 나와야 다음 단계로 갑니다.
4. **`[상투어]`, `[리듬]`, `[대시]`는 참고용입니다.** 실제로 어색할 때만 고치고, 자연스러운 문장은 그대로 둡니다. 고칠 때는 아래 원칙을 따릅니다.
   - 짧은 문장이 3개 넘게 이어지면 `-는데`, `-면서`, `-기 때문에` 같은 연결어미나 관형절로 이유와 결과를 한 문장 안에서 잇습니다.
   - "중요한 역할을 합니다", "~에 대해 알아보겠습니다"처럼 뜻이 비어 있는 문장은 구체적인 사실로 바꾸거나 지웁니다.
   - 이중 피동(되어지다), "가지고 있다" 직역, "~에 있어서"는 자연스러운 한국어로 바꿉니다.
5. **바꾸면 안 되는 것을 다시 대조합니다.** 직접 인용, 고유명사, 숫자와 단위, 날짜, URL, 광고·제휴 고지, 법적 고지, 실제로 쓴 프롬프트는 글자 그대로 둡니다.

## 하지 않는 것
- 사람처럼 보이려고 없는 경험, 감정, 일화, 수치를 지어내지 않습니다.
- 일부러 오탈자나 비문을 넣지 않습니다. "AI 탐지 회피"를 약속하지 않습니다.
- 검사 결과나 점수를 공개 글에 넣지 않습니다.
- 글 전체를 여러 번 통째로 다시 쓰지 않습니다. 문제가 있는 구간만 고칩니다.

## 한계
- 종결어미 판정은 규칙 기반이라 "~거든요", "~잖아요" 같은 구어체 해요체나 시적인 문장은 틀리게 분류될 수 있습니다. `[말투]` 결과는 사람이 한 번 더 확인합니다.
- 상투어 목록은 작성자가 실제 글을 고치며 모은 짧은 목록입니다. 더 깊은 분석이 필요하면 [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 분류 체계를 참고하세요.
