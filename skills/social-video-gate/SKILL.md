# 소셜 영상 비율 검사 (social-video-gate)

세로로 찍은 줄 알았던 영상이 업로드하자 옆으로 누워 있거나, 가로 영상이 릴스에 올라가 위아래가 검게 비는 일은 생각보다 자주 생깁니다. 파일 속 가로·세로 숫자만 보면 놓치는 경우가 두 가지 있기 때문입니다.

- **회전 정보**: 휴대폰 영상은 1920x1080으로 저장하고 "90도 돌려서 보여 줘"라는 표시만 붙이는 경우가 많습니다. 화면에는 1080x1920 세로로 보입니다.
- **픽셀 비율(SAR)**: 픽셀 하나가 정사각형이 아닌 영상은 저장된 크기와 보이는 크기가 다릅니다. 업로드하는 곳이 이 값을 무시하면 사람 얼굴과 글자가 늘어나거나 찌그러집니다.

이 스킬은 두 가지를 모두 계산해 **화면에 실제로 보이는 크기**로 판단합니다.

## 준비
- Node 18 이상
- FFmpeg의 `ffprobe` (PATH에 있거나 `FFPROBE_PATH` 환경변수로 지정)

## 사용
```bash
node scripts/video-gate.mjs final.mp4 --target reels
node scripts/video-gate.mjs final.mp4 --target youtube --json
```

| target | 비율 | 최소 | 권장 |
|---|---|---|---|
| `reels`, `shorts`, `tiktok` | 9:16 세로 | 720x1280 | 1080x1920 |
| `youtube`, `threads-landscape` | 16:9 가로 | 1280x720 | 1920x1080 |
| `square` | 1:1 | 720x720 | 1080x1080 |

비율은 1%까지 오차를 허용합니다(1080x1918도 9:16으로 봅니다). 해상도는 비율이 맞을 때만 판단합니다.

## 결과 읽기
- `PASS`(종료 코드 0): 비율과 최소 해상도를 통과했습니다.
- `FAIL`(종료 코드 1): 비율이 다르거나, 해상도가 너무 낮거나, 픽셀 비율이 정사각형이 아니거나, 영상 스트림이 없습니다. **이때는 게시하지 않습니다.**
- 종료 코드 2: 파일이 없거나 ffprobe를 실행하지 못했습니다.
- `!` 줄은 경고입니다. 회전 정보로만 방향이 바뀌는 파일, 소리 없는 파일, 흔하지 않은 프레임 속도를 알려 줍니다. 게시를 막지는 않지만 확인해 볼 만합니다.

## 고치는 법
- 픽셀 비율 문제: `ffmpeg -i in.mp4 -vf "scale=1080:1920,setsar=1" -c:a copy out.mp4`
- 회전 정보를 실제 픽셀에 적용: 최신 FFmpeg는 다시 인코딩할 때 회전을 자동으로 적용하므로 `ffmpeg -i in.mp4 -c:v libx264 -c:a copy out.mp4`로 새로 만든 뒤 다시 검사합니다.
- 비율이 다른 영상을 억지로 늘리지 않습니다. 잘라 내거나(crop) 여백을 넣는(pad) 방식으로 다시 편집하고, 중요한 글자나 얼굴이 잘리지 않았는지 확인합니다.

## 꼭 알아 둘 것
- 이 검사는 **파일의 기술 규격만** 봅니다. PASS가 나와도 각 플랫폼의 실제 업로드 미리보기에서 화면이 늘어나거나 찌그러지지 않았는지, 위아래 UI에 자막과 얼굴이 가리지 않는지 **직접 눈으로 확인**해야 합니다.
- 파일을 고친 뒤에는 검사를 다시 돌립니다. 이전 결과를 그대로 쓰지 않습니다.
- 플랫폼 권장 규격은 바뀔 수 있습니다. 표의 숫자가 최신 공식 안내와 다르면 스크립트의 `TARGETS` 값을 고쳐 씁니다.
