# 노트 저장고에서 먼저 찾아보기 (vault-recall)

에이전트는 매번 새로 깨어나기 때문에, 지난주에 고친 실수를 이번 주에 그대로 반복하곤 합니다. 이 스킬은 작업을 시작하기 전에 노트 저장고를 한 번 검색해 관련 기록 몇 개를 먼저 읽게 하는 습관을 만듭니다. 작성자는 8,000개가 넘는 노트에서 이 방식으로 "예약 공개 영상의 고정 댓글을 빠뜨린 일" 같은 기록을 작업 직전에 다시 찾아 씁니다.

## 절차
1. **이번 작업을 한 줄로 적어 검색합니다.** 도구 이름, 채널, 겪을 만한 문제를 같이 넣으면 잘 찾습니다.
   ```bash
   node scripts/recall.mjs ~/MyVault "유튜브 쇼츠 예약 공개 고정 댓글" --top 5
   node scripts/recall.mjs ~/MyVault "TTS 끝소리" --tags tts,voice --json
   ```
   `--json` 결과의 `read_next`에 가장 관련 있는 노트 두 개의 경로가 들어 있습니다.
2. **`read_next` 노트를 최대 두 개까지 원문으로 읽습니다.** 요약만 보고 판단하지 않습니다.
3. **지금 작업에 맞는 것만 적용합니다.**
   - 노트 상태가 '미검증', '추정', draft라면 단서로만 쓰고 그대로 규칙처럼 따르지 않습니다.
   - 사용자의 최신 지시와 노트 내용이 다르면 최신 지시가 이깁니다.
4. **결과에 무엇을 참고했는지 남깁니다.** "참고한 노트: ○○ (적용함 / 해당 없음)"처럼 한 줄이면 됩니다. 검색하지 않았다면 "배운 내용을 반영했다"고 말하지 않습니다.
5. 작업에서 새로 알게 된 것이 있으면, 사용자가 원할 때만 저장고에 새 노트로 남깁니다. 이 스킬은 기본적으로 노트를 읽기만 합니다.

## 점수 계산
- 제목 일치 3배, 태그 일치 2배, 본문 일치 1배(긴 노트는 길이로 나눠 공평하게 맞춥니다)
- 한국어는 두 글자씩 끊어 비교하기 때문에 띄어쓰기나 조사가 달라도 찾습니다. 영어는 단어 단위로 비교합니다.
- front matter의 `status`가 verified·확인이면 +30%, 미검증·unverified·draft면 -15%, 최근 30일 안에 바뀐 노트는 +10%입니다.
- 색인은 `<저장고>/.recall-cache.json`에 저장되고, 바뀐 파일만 다시 읽습니다. 작성자의 저장고(노트 8,017개)에서 처음 3.4초, 그다음부터 0.6초 걸렸습니다. 파일을 하나도 쓰지 않으려면 `--no-cache`를 붙입니다.

## 한계
- 뜻이 같은 다른 단어(예: "썸네일"과 "미리보기 이미지")는 찾지 못합니다. 결과가 없으면 표현을 바꿔 한 번 더 찾습니다.
- 점수가 높다고 그 노트가 옳다는 뜻은 아닙니다. 노트의 상태와 날짜를 보고 판단합니다.
- `.obsidian`, `.git`, `.trash` 폴더는 건너뜁니다.
